1. 项目概览：它是如何工作的？

这是一个全栈 AI 股票分析面板。用户在前端输入股票代码，后端自动获取实时行情和 K 线数据，然后调用 DeepSeek 大模型对股票进行专业分析，最后将分析结果存入 Supabase 数据库。

核心工作流程（从用户点击到页面展示）：

1. 用户输入
股票代码
→
2. 前端调用
/api/stock/:symbol
→
3. 后端多级
数据源查询
→
4. 返回行情
展示卡片
→
5. 调用
/api/analyze
→
6. DeepSeek
LLM 分析
→
7. Supabase
存储结果
→
8. 前端展示
AI 分析卡片
关键技术决策：前后端一体部署（FastAPI 同时提供 API 和静态文件），避免 CORS 问题；多级数据源降级（Twelve Data → yfinance → Finnhub）确保美股数据可用性；LLM 调用采用 4 层容错机制保证前端永远不会崩溃。

3.1 backend/main.py — FastAPI 入口 & CORS & 静态文件

这是整个应用的启动入口，只做三件事：创建 FastAPI 实例、配置 CORS 中间件、挂载路由和静态文件。

逐段分析：

# 1. 创建 FastAPI 应用实例
app = FastAPI(title="Stock AI Dashboard", version="1.0.0")

# 2. CORS 中间件 — 开发阶段允许所有来源跨域访问
#    allow_origins=["*"] 表示任何域名的前端都能调这个 API
#    Render 部署后前后端同源，CORS 实际不起作用，但保留作为安全兜底
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

# 3. 注册路由 — 三个业务路由挂到 /api 前缀下
from backend.routers import stock, analysis, candles
app.include_router(stock.router, prefix="/api")
app.include_router(analysis.router, prefix="/api")
app.include_router(candles.router, prefix="/api")

# 4. 健康检查接口
@app.get("/api/health")
def root():
    return {"message": "Stock AI Dashboard API is running"}

# 5. 静态文件托管 — 把 frontend/ 目录映射到根路径 "/"
#    html=True 表示找不到文件时回退到 index.html (SPA 模式)
from fastapi.staticfiles import StaticFiles
frontend_dir = os.path.join(os.path.dirname(__file__), "..", "frontend")
if os.path.isdir(frontend_dir):
    app.mount("/", StaticFiles(directory=frontend_dir, html=True), name="frontend")
关键点：app.mount("/", StaticFiles(...), ...) 必须放在所有路由注册之后，否则静态文件会拦截所有请求。访问 / 返回 index.html，访问 /interview.html 返回面试文档页面，API 请求由路由优先处理。

3.3 backend/models/schemas.py — Pydantic 数据模型

定义了 API 请求/响应的数据结构约束。FastAPI 会根据这些模型自动校验数据、生成 API 文档。

class StockData(BaseModel):
    """POST /api/analyze 的请求体：前端传什么数据给 AI 分析"""
    symbol: str                              # 股票代码，如 "AAPL"
    price: float                             # 当前价格
    change: float                            # 涨跌金额
    change_percent: str                       # 涨跌百分比，如 "+2.35%"
    volume: int = 0                        # 成交量，默认 0
    market: Optional[str] = None           # "us" 或 "china"，用于前端货币符号
    candles: Optional[list] = None        # K线数据数组，可选

class AIAnalysisResult(BaseModel):
    """POST /api/analyze 的响应体：AI 分析必须返回这三个字段"""
    summary: str                                       # AI 分析总结
    sentiment: Literal["Bullish", "Neutral", "Bearish"]  # 情绪：仅限这三者
    risk_level: str                                      # 风险等级
为什么用 Literal 类型？FastAPI 会自动校验 sentiment 字段值必须是 Bullish/Neutral/Bearish 之一，如果 LLM 返回了其他值，API 会在返回给前端之前就报错。配合 llm_service.py 中的 _validate_and_return() 函数做双重保障。

3.4 backend/routers/stock.py — 股票行情接口

职责：接收前端发来的股票代码，调用 stock_service 查询行情，返回 JSON。

@router.get("/stock/{symbol}")            # GET /api/stock/AAPL
async def get_stock(symbol: str):       # {symbol} 自动从 URL 路径提取
    try:
        data = await get_stock_quote(symbol)  # 调用核心服务
        return data
    except ValueError as e:

路由层只做两件事：(1) 接收 HTTP 请求参数；(2) 把异常转成合适的 HTTP 状态码。业务逻辑全部封装在 services 层，这叫"关注点分离"。

3.6 backend/routers/analysis.py — AI 分析 + 历史记录

核心接口：接收前端传来的完整股票数据（含 K 线），调用 LLM 分析后存入 Supabase。

@router.post("/analyze", response_model=AIAnalysisResult)
async def analyze(request: StockData):          # FastAPI 自动把 JSON body 转成 StockData 对象
    # Step 1: 调用 LLM 分析
    analysis = await analyze_stock(request.model_dump())  # model_dump() 把 Pydantic 对象转 dict

    # Step 2: 构造存储记录
    record = {
        "symbol": request.symbol,
        "price": request.price,
        "change_percent": request.change_percent,
        "market": request.market,
        "summary": analysis["summary"],
        "sentiment": analysis["sentiment"],
        "risk_level": analysis["risk_level"],
        "created_at": datetime.now(timezone.utc).isoformat(),  # UTC 时间戳
    }

    # Step 3: 写入 Supabase
    save_analysis(record)

    return analysis

@router.get("/history") 取最近 5 条分析记录（按 created_at 降序），用在前端底部展示区。

3.7 backend/services/stock_service.py — 美股多级降级 + A股分流

这是行情查询的调度中心。入口函数 get_stock_quote() 根据代码特征自动分流，美股走三级降级链。

核心入口：

async def get_stock_quote(symbol: str) -> dict:
    resolved = symbol.strip().upper()

    # 判断是否为A股：纯数字6位 → 中国股票
    if is_china_stock(resolved):
        result = await get_china_stock_quote(resolved)
        result["market"] = "china"   # 标记市场，前端据此用 ¥ 符号
        return result

    # 美股三级降级链
    # Level 1: Twelve Data
    td_result = await get_twelve_data_quote(resolved)
    if td_result is not None and td_result.get("price", 0) > 0:
        td_result["market"] = "us"
        return td_result                     # ← 注意：Twelve Data 免费版 volume 可能为0

    # Level 2: yfinance (同步调用，因为 yfinance 库不是 async 的)
    yf_result = _get_us_quote_from_yf(resolved)
    if yf_result is not None and yf_result.get("price", 0) > 0:
        yf_result["market"] = "us"
        return yf_result                     # yfinance 含真实成交量

    # Level 3: Finnhub
    fh_result = await _get_finnhub_quote(resolved)
    if fh_result is not None and fh_result.get("price", 0) > 0:
        fh_result["market"] = "us"
        return fh_result

    # 全部失败
    raise ValueError(f"Cannot get quote for {symbol}, check the ticker")

成交量补齐机制：

yfinance 路径每次都会调用 _get_us_volume() 获取真实成交量（带缓存+重试+节流）。Finnhub 路径同样调用了这个函数。但 Twelve Data 路径原来遗漏了——这就是 Bug 3 "美股成交量为0"的根因。修复方式是在 Twelve Data 返回后也调用 _get_us_volume() 补齐。

def _get_us_volume(symbol: str) -> int:
    # 1. 先查缓存（5分钟 TTL）
    cached = yf_cache.get(f"vol:{symbol}")
    if cached is not None:
        return cached

    # 2. 通过 yfinance 取最近5天数据，拿最后一天的成交量
    ticker = yf.Ticker(symbol)
    for attempt in range(3):                   # 重试3次
        try:
            yf_throttle.acquire()          # 节流：两次调用间隔 ≥ 3秒
            hist = ticker.history(period="5d")
            if not hist.empty:
                vol = int(hist["Volume"].iloc[-1])
                yf_cache.set(f"vol:{symbol}", vol)
                return vol
        except Exception as e:
            if attempt < 2:
                time.sleep((2 ** attempt) * 2 + random.uniform(0, 1))  # 指数退避
    return 0  # 全部失败则返回 0

3.9 backend/services/china_stock_service.py — 新浪财经A股接入

从新浪财经的免费接口获取 A 股实时行情。解析老式 var 赋值格式是本文件的核心逻辑。

新浪数据格式与解析：

# 新浪返回的原始格式（JS var 赋值语句）：
# var hq_str_sh600036="招商银行,43.50,43.00,43.80,44.00,..."

# 解析步骤：
# 1. 用正则提取引号内的 CSV 字符串
match = re.search(r'"([^"]*)"', text)

# 2. 按逗号分割得到字段数组
#    索引0=名称, 1=今开, 2=昨收, 3=现价, ..., 8=成交量(手)
fields = match.group(1).split(",")

# 3. 提取关键字段
name = fields[0]        # 股票名称，如 "平安银行"
open_price = float(fields[1])
prev_close = float(fields[2])   # 昨日收盘价
current = float(fields[3])      # 当前价格
volume = int(fields[8])        # 成交量（手）

change = round(current - prev_close, 3)
change_percent = f"{(change / prev_close * 100):.2f}%"

代码转新浪格式：

def _resolve_sina_code(raw: str) -> str:
    s = raw.strip().upper()
    if s[0] in ("0", "3"):
        return f"sz{s}"    # 深圳交易所: sz000001
    if s[0] == "6":
        return f"sh{s}"    # 上海交易所: sh600036
    return s
为什么用新浪而不是 Finnhub？Finnhub 的A股数据需要带后缀（.SS/.SZ），且免费版覆盖不全。新浪财经 API 免费、无需 Key、数据实时，是 A 股数据的最佳免费选择。

3.10 backend/services/candle_service.py — K线多数据源

async def get_candles(symbol, period="3mo", interval="1d"):

    if _is_china_stock(resolved):

3.11 backend/services/llm_service.py — DeepSeek AI 分析核心

这是整个项目最核心的文件。它负责：构造 Prompt、调用 DeepSeek、解析 JSON、多层容错。

3.11.1 延迟初始化客户端：

# 为什么用延迟初始化而不是模块顶层创建？
# 如果 DEEPSEEK_API_KEY 未设置，模块导入时不会报错，只有实际调用时才抛异常

_client: AsyncOpenAI | None = None

def _get_client() -> AsyncOpenAI:

    if _client is None:
        _client = AsyncOpenAI(
            api_key=DEEPSEEK_API_KEY,
            base_url="https://api.deepseek.com",  # OpenAI SDK 兼容 DeepSeek
        )

3.11.2 System Prompt 设计：

SYSTEM_PROMPT = '''你是一个专业的股票分析师。用户会提供股票的实时行情数据...

请严格按以下 JSON 格式返回分析结果，不要包含任何其他文字、解释或 Markdown 标记：

{
  "summary": "用1-5句中文总结...",
  "sentiment": "Bullish 或 Neutral 或 Bearish",
  "risk_level": "Low Risk 或 Medium Risk 或 High Risk"
}

规则：
- sentiment 只能是 Bullish、Neutral、Bearish 之一
- risk_level 只能是 Low Risk、Medium Risk、High Risk 之一
- 只返回 JSON 对象，不要用代码块包裹
- 所有字段都必须有值，不能为空字符串'''
Prompt 设计原则：(1) 明确格式约束——"只返回 JSON"；(2) 枚举值约束——写清楚可选值；(3) 负面约束——"不要有任何前缀或后缀文字"。这三层约束层层递进，从源头减少 LLM "乱说话"的可能。

3.11.3 K线技术指标摘要：

_build_candle_summary() 函数从原始 K 线数据（开/高/低/收/量数组）中计算出以下技术指标，拼成一段文字传给 LLM：

  • 区间极值：period_high、period_low（最高/最低价）
  • 期间涨跌幅：(最新收盘 - 最早收盘) / 最早收盘
  • 价格分位：当前收盘在区间中的百分比位置
  • 移动均线：MA5、MA10、MA20 及与现价的关系
  • 成交量趋势：近5日 vs 前5日对比，判断放量/缩量/持平

3.11.4 API 调用配置（三重稳定性保障）：

response = await _get_client().chat.completions.create(
    model="deepseek-chat",
    messages=[...],
    temperature=0.3,                              # 低温度：输出更确定性，减少随机性
    response_format={"type": "json_object"},    # 模型层强制输出 JSON
)
  • temperature=0.3：低温度让模型输出更"保守"、更可预测，减少随机插入闲聊文字的概率
  • response_format={"type": "json_object"}：DeepSeek 在 API 层面就保证输出是合法 JSON，这是最有力的一层保障
  • 4 层容错（见下方）：即使 DeepSeek 违抗了以上所有约束，代码层面仍有兜底

3.11.5 4 层 JSON 解析容错机制：

// ===== Layer 1: 理想路径 — 直接 json.loads =====
try:
    result = json.loads(content)            # 纯 JSON → 一次成功
    return _validate_and_return(result)
except json.JSONDecodeError:
    // ===== Layer 2: 正则暴力提取 =====
    match = re.search(r'\{.*\}', content, re.DOTALL)  # "好的，分析如下：{...}" → 提取 {...}
    if match:
        result = json.loads(match.group())
        return _validate_and_return(result)

    // ===== Layer 3: 自动重试（最多2次）=====
    if retry < 2:
        return await analyze_stock(stock_data, retry + 1)  # 递归重试

    // ===== Layer 4: 最终降级 =====
    return {
        "summary": "AI 分析暂时不可用",
        "sentiment": "Neutral",
        "risk_level": "Medium Risk",
    }
设计理念：永远不要让前端崩溃。即使 LLM 完全乱说、网络超时、API 欠费，前端用户看到的永远是一个合法的分析结果卡片——最坏情况就是显示"AI 分析暂时不可用"，而不是白屏或报错。

3.11.6 字段验证函数：

def _validate_and_return(data: dict) -> dict:
    # 如果 LLM 返回了不在枚举范围内的值，强制纠正为默认值
    if sentiment not in {"Bullish", "Neutral", "Bearish"}:
        sentiment = "Neutral"
    if risk not in {"Low Risk", "Medium Risk", "High Risk"}:
        risk = "Medium Risk"
    return {"summary": data.get("summary", "")[:200],  # 截断超长文本
            "sentiment": sentiment,
            "risk_level": risk}

4.3.2 核心分析流程（三阶段串行）：

async function analyzeStock() {
    // 防重复点击：按钮 disabled 期间无法再次触发
    if (analyzeBtn.disabled) return;

    setLoading(true);

    // Phase 1: 获取行情 → 渲染卡片
    const stockData = await fetchStock(symbol);
    renderStockCard(stockData);

    // Phase 2: 获取K线 → 渲染图表（失败不阻塞主流程）
    try {
        candleData = await fetchCandles(symbol);
        renderChart(candleData);
    } catch (err) {
        chartCard.style.display = 'none';  // K线失败就隐藏图表区
    }

    // Phase 3: AI 分析（传入行情和K线）→ 渲染分析卡片
    const analysis = await fetchAnalysis(stockData, candleData);
    renderAnalysisCard(analysis);

    setLoading(false);
}

6. 核心设计模式总结

模式具体体现
关注点分离 routers（HTTP层）/ services（业务逻辑）/ models（数据结构）三层分离，每层只做一件事
降级策略 美股数据三级降级（Twelve Data → yfinance → Finnhub）；LLM 解析四层容错；K线获取二级降级
延迟初始化 DeepSeek 客户端和 Supabase 客户端在首次调用时才初始化，避免缺少环境变量时应用启动崩溃
字段级数据补齐 成交量从 yfinance 单独获取，与价格数据源解耦，解决免费 API 字段不完整的问题
缓存 + 节流 TTL 缓存（5分钟过期）减少重复请求；速率限制器避免触发 API 频率上限
优雅降级 K线获取失败不影响主流程（隐藏图表区继续展示分析）；LLM 失败返回兜底 JSON
前后端一体部署 FastAPI StaticFiles 托管前端，消除 CORS 问题，简化部署（一个 Render 服务即可）
双重可观测性 前端 Debug 面板 + 浏览器 Console + 后端 print() 日志，三层日志覆盖全链路
